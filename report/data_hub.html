수행평가 데이터허브
구축 기획

전국 학교 평가계획을 표(DB)로 한 번 쌓아, 조회·코칭·콘텐츠에 재사용
작성 2026-09-22 · 신상준(CGO) · 소스: 학교알리미(공공누리 제1유형) · 연계 문서: 1부「블로그 에이전트 기획」
핵심 개념
전국 학교의 수행평가 계획을 구조화된 표(DB)로 한 번 구축하면, 조회기 · 코칭 에이전트 · 블로그 세 가지로 재사용됩니다. 데이터 하나, 활용 여럿.

1. 데이터가 중심이다

블로그는 활용처 중 하나일 뿐입니다. 핵심은 잘 구조화된 데이터(표)를 한 번 쌓는 것. 표가 튼튼하면 그 위에 여러 도구가 얹힙니다.

왜 이 구조가 강력한가: 데이터를 세 번 만드는 게 아니라 한 번 쌓아 세 곳에서 재사용. 게다가 이 데이터는 학교알리미 PDF·HWP를 파싱해야 나오는 것이라 경쟁사가 못 가진 독점 자산입니다.

2. 데이터 표 설계 (스키마)

세 용도에 모두 맞으려면 표에 아래 항목이 담겨야 합니다. ● 필수 / ○ 선택(있으면 파싱).

컬럼예시필수어디에 쓰나
region서울 강북구●지역 필터·검색, 블로그 태그
school삼각산중●검색, 블로그 제목, 학생 매칭
grade2학년●학년 필터, 코칭 매칭
term2학기●학기 필터
subject국어●과목별 표시
jipil_pct40●지필 비율 — 표시·분석
suhaeng_pct60●수행 비율 — 표시·분석
task_name토론, 서평 쓰기●수행과제 — 코칭 핵심
eval_time10월 3주○평가시기 — 코칭 에이전트에 필수 (학교 문서에 있을 때만)
std_code9국01-02○성취기준 — 심화 분석용
source_url학교알리미 링크○출처표시(공공누리 의무)
updated2026-09●갱신 관리(연 2회)
eval_time(평가시기)이 관건: 코칭 에이전트("이 아이 다음 주 영어 말하기 수행 있으니 준비")를 하려면 시기가 필요합니다. 학교 평가계획 문서에 시기가 명시된 경우만 파싱 가능 — 있으면 코칭이 강력해지고, 없으면 비율·과제만으로 운영합니다.

저장 위치: 구글 시트 (기존 인프라 재사용)

  • 파싱 결과를 구글 시트에 한 행씩 적재 (학교×학년×학기×과목 = 한 행)
  • 조회기·코칭·블로그가 모두 이 시트를 gviz로 읽음 — 대시보드(total.html)와 동일 방식
  • 이미 검증된 인프라라 새로 배울 것 없음. 나중에 규모 커지면 Firestore로 이전 가능

3. 데이터는 어떻게 채우나 (PoC 통과)

[1] 학교 UUID(SHL_IDF_CD) 수집       ← 지역별 페이지 순회
[2] 평가계획 첨부파일 링크 확보       ← Ajax 호출
[3] 파일 다운로드 (PDF/HWP/XLSX)     ← EiFileDownLoad.do
[4] 텍스트 추출 (변환 없이)
[5] AI 구조화 파싱 → 위 스키마의 JSON  ← 핵심 (규칙파싱 불가, AI만 가능)
[6] 구글 시트에 적재
구분내용
✅ 검증됨파일 다운로드 경로, 3종 포맷 텍스트 추출, AI 파싱 방식, 샘플 2교(삼각산중·대방중), 상업이용 합법
🔶 남은 관문① 평가계획 항목번호(GS_HANGMOK_CD) 확정 ② Ajax 파일목록 구조 ③ UUID 대량 수집 경로

4. 활용처별 상세

① 조회기 (상담·학부모)

  • 학교 검색창 + 지역 필터 → 학교 선택 → 과목별 지필/수행 비율표 표시
  • 상담 시 "댁 자녀 학교, 이번 학기 수행이 이렇습니다" 즉시 제시 → 신뢰·전문성
  • 대시보드와 같은 웹페이지(HTML+gviz)로 구축

② 수행평가 코칭 에이전트 (담임 관리)

  • 학생의 학교·학년 입력(또는 노션 CRM 자동 매칭) → 그 학생이 볼 수행평가 목록
  • 다가오는 평가 시기·과제 알림 + "이 과제는 이렇게 준비" 코칭 가이드
  • 담임이 학생 관리 상담할 때 근거 자료로 사용 — 관리형 브랜드의 실체

③ 블로그 (SEO 유입)

  • 학교당 글 1개 자동 생성 ("[○○중] 수행평가 총정리") → 학교명 검색 독점
  • 하루 3~5개씩 리드 학교부터 발행 (저품질 방지)

5. 실행 로드맵

1
스키마 확정 + 조회기 껍데기  위 표 구조로 구글 시트 설계 + 조회기 UI를 샘플 데이터(삼각산중·대방중)로 먼저 구축 → "이렇게 쌓이고 조회된다" 확인
2
파싱 관문 해결  GS_HANGMOK_CD 확정(F12) → UUID 수집 → 파싱 파이프라인 코드화
3
Phase 0 파일럿  리드 밀집 1개 지역 30개교 파싱 → 시트 적재 → 조회기에 실데이터 표시
4
Phase 1 리드 학교 전체  노션 CRM 리드 학교 우선 파싱 → 조회기·코칭·블로그 동시 가동
5
Phase 2~3 확장  수도권(1,500교) → 전국(중3,200+고1·2) · 연 2회 자동 갱신
순서의 핵심: 데이터가 없어도 스키마 확정 + 조회기 껍데기부터 만든다. 표 구조가 확정되면 파싱은 그 형식으로 채우기만 하면 되고, 코칭·블로그도 같은 표를 읽으면 된다. 표가 먼저, 활용은 그 위에.
핵심: 수행평가 데이터허브 = 아라온의 독점 데이터 인프라. 학교알리미에 흩어진 평가계획을 구조화 표로 한 번 쌓으면 → 조회기(상담)·코칭 에이전트(관리)·블로그(유입) 셋으로 재사용된다. 경쟁사는 이 데이터가 없어 못 만든다. 표를 먼저 튼튼히 설계하는 것이 전체의 토대다.
